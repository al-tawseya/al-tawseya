التوصية — نسخة v3

ما الجديد:
1) حساب مستخدم حقيقي (اسم + هاتف + كلمة مرور) ويحفظ تسجيل الدخول على الجهاز.
2) سلة طلبات: يمكن جمع عدة إعلانات ثم دفع 1 دينار لكل إعلان في دفعة واحدة.
3) طلبات المستخدم تبقى مرتبطة بالحساب، ويمكن الرجوع لها من «حسابي» بعد تحديث الصفحة.
4) اسم المحوّل في الدفع بدل رقم المرجع.
5) لوحة الإدارة تعرض الدفعة كاملة مع اسم المحوّل والمبلغ وعدد الإعلانات.
6) رابط متجر مستقل لكل إعلان، ولا يصل للمتصفح قبل اعتماد الدفع.
7) صندوق اقتراحات للمستخدمين.
8) Gemini محدث إلى google-genai مع gemini-2.5-flash لفهم اللهجة الأردنية/العربية المختلطة وإعادة ترتيب النتائج دلاليًا.
9) نقطة Webhook مستقبلية للمدفوعات في /api/payments/incoming للمطابقة الآلية عندما يتوفر مصدر موثوق لإشعارات CliQ.

Environment Variables في Render:
- ADMIN_PASSWORD = كلمة مرور لوحة الإدارة
- GOOGLE_API_KEY = مفتاح Gemini الموجود لديك أصلًا
- GEMINI_MODEL = gemini-2.5-flash (اختياري؛ هذا هو الافتراضي)
- PAYMENT_WEBHOOK_SECRET = سر طويل وعشوائي (اختياري الآن؛ يستخدم لاحقًا عند ربط إشعارات الدفع)
- PAYMENT_ALIAS = MQRB (اختياري)
- PAYMENT_BANK_AR = البنك العربي (اختياري)
- DATABASE_FILE = decision_engine.db (افتراضي)

مهم للتشغيل التجاري:
Render Free يستخدم نظام ملفات مؤقتًا؛ SQLite المحلية قد تفقد البيانات بعد إعادة التشغيل/إعادة النشر. عند بدء استقبال مستخدمين فعليين يجب نقل قاعدة البيانات إلى Render Postgres أو خدمة بيانات دائمة.

مهم للروابط:
العروض التجريبية الحالية تستخدم روابط وهمية/عامة. من لوحة /admin يجب إدخال رابط المتجر الحقيقي لكل عرض. الرابط العام مثل https://wa.me أو https://instagram.com لن يُقبل.

مهم للدفع الآلي:
الموقع لا يستطيع من صفحة ويب عادية قراءة رسائل SMS الموجودة على هاتفك. عند تنفيذ الأتمتة لاحقًا، الأفضل ربط الموقع بمصدر موثوق للحركة: تكامل تاجر/محصل CliQ رسمي، أو وسيط/جسر موثوق يرسل إشعار الحوالة إلى /api/payments/incoming. نقطة الـWebhook تقارن الاسم والمبلغ، وإذا كان التطابق وحيدًا تعتمد الدفعة تلقائيًا.
